Core Architecture

Understanding the data flow from player machines to the broadcast production deck.

UDP/SRT Ingestion Engine

Live Forge bypasses HDMI capture cards by intercepting network packets. Player PCs use OBS to encode their gameplay and push it as a continuous UDP transport stream over the local Gigabit switch.

Automated Rolling Buffer

The engine continuously writes `.ts` (Transport Stream) chunks to a dedicated SSD directory. An internal chron-job monitors directory size and automatically deletes oldest chunks, maintaining a persistent 5-minute memory loop without bloat.

DXVA2 / CUDA Acceleration

Software decoding 10+ high-bitrate streams simultaneously will crash a CPU. Live Forge pipelines the FFmpeg decoding process directly to your NVIDIA GPU (CUDA) or Intel iGPU (QSV), leaving the CPU free for OBS rendering.

OBS WebSocket v5 Sync

Live Forge operates as a master controller for OBS. When a replay is triggered, the engine connects via WS port 4455, changes the active OBS Scene to "Replay", plays the media source, and automatically cuts back to "Live" upon completion.

Strict Hardware Tolerances

To prevent dropped frames, network stuttering, and stream desyncs, your physical event infrastructure must meet these minimum specifications.

Network Topology

  • Core Switch Layer A 1000 Mbps (Gigabit) unmanaged switch is strictly mandatory. A 10-player LAN pushing 10,000 Kbps each will instantly saturate and crash a 100 Mbps switch.
  • Physical Cabling Cat6 or Cat5e Ethernet cables only. Do not attempt to run UDP video streams over venue Wi-Fi.
  • IP Configuration Ensure all Player PCs and the Production PC are on the same subnet (e.g., 192.168.1.X) with no AP Isolation enabled on the router.

Production Rig

  • GPU Specifications NVIDIA RTX 3050, 3060, or 40-series required. The NVENC/NVDEC chips are critical for maintaining stream stability during multi-cam extraction.
  • Storage Bandwidth A dedicated USB 3.1 Type-C External SSD (e.g., Samsung T7) is required solely for the Video Buffer. Writing 10 continuous video streams to your OS Drive (C:) will cause system-wide lockups.
  • Processing Power Intel Core i5 (12th Gen+) or AMD Ryzen 5 (5000 Series+) with a minimum of 16GB dual-channel RAM.

Advanced Setup Guide

Exact configuration parameters for the Player PCs to ensure the video streams are readable by the Live Forge ingestion engine.

Step 1

Player PC OBS Configuration

On every player's machine, open OBS Studio. Go to Settings > Output. Change the Output Mode to Advanced, and navigate to the Recording tab. Apply these exact Custom FFmpeg settings:

Parameter Required Setting
Type Custom Output (FFmpeg)
FFmpeg Output Type Output to URL
File path or URL udp://[PRODUCTION_PC_IP]:[PORT]?pkt_size=1316
(e.g., udp://192.168.1.100:5001?pkt_size=1316)
Container Format mpegts
Video Bitrate 8000 Kbps - 15000 Kbps (depending on switch capacity)
Keyframe interval 1 or 2 (Critical: High keyframes prevent trimming errors)
Video Encoder nvenc_h264 or h264_qsv (Hardware encoding only)
Step 2

Connecting the Engine

On the Production PC, launch Live Forge. In the Camera Profile settings, add the corresponding UDP URLs that you configured on the Player PCs. Ensure you increment the ports for each player (e.g., Player 1 is 5001, Player 2 is 5002).

// Live Forge Camera URL Format udp://@0.0.0.0:5001 udp://@0.0.0.0:5002 udp://@0.0.0.0:5003
Step 3

OBS Studio WebSocket Sync

For automated transitions, Live Forge must communicate with the OBS instance running your main broadcast.

  1. In the Production PC's OBS, go to Tools > WebSocket Server Settings.
  2. Check "Enable WebSocket server" and ensure it is running on Port 4455.
  3. Create a specific Scene in OBS named exactly Replay.
  4. Add a Media Source to that scene pointing to the Live Forge output folder.
  5. Enter your WebSocket Password into the Live Forge settings panel.

Troubleshooting & FAQ

Common issues encountered during live tournament deployments.

The video buffer is stuttering or dropping frames.

This is almost always a network bottleneck. Ensure your switch is truly Gigabit (1000 Mbps). If the switch is Gigabit, verify that the Player PCs are using Cat6 cables. If cables are fine, lower the Player PC OBS Video Bitrate from 15000 Kbps down to 8000 Kbps.

When I extract a clip, the first few seconds are frozen.

This occurs when the Player PC's OBS has a Keyframe Interval set to 0 (Auto) or too high (e.g., 250). FFmpeg requires frequent keyframes to accurately cut `.ts` files. Ensure the Player PC OBS Keyframe Interval is hardcoded to 1 or 2.

Live Forge cannot connect to OBS WebSocket.

Verify that your Windows Defender Firewall is not blocking port 4455 on your Private Network. Additionally, ensure you have OBS WebSocket v5.x installed (it comes native with OBS v28 and higher; older versions use an incompatible v4 plugin).
